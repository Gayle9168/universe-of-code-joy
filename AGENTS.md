# Algora — Agent Development Directives & Strict Instructions

These rules are **MANDATORY** for any AI agent or developer working on the Algora codebase. Every instruction must be strictly adhered to without exception.

---

## 1. Zero UI Structure & Pixel Drift (Wiring Only)

- **Do NOT alter UI layouts, structure, margins, paddings, or visual styling.**
- When implementing interactivity (Roadmap steps), your job is **wiring only**: bind state, connect handlers, attach stores, and update data flow without changing existing DOM hierarchy, CSS token classes, or pixel alignment.
- Always retain existing visual components, layout grids, responsive wrappers, and typography.
- Never add or remove visual containers unless explicitly specified in the user request.

---

## 2. No Guessing — Always Read Before Action

- **Never guess** file paths, exports, types, interfaces, schemas, or function signatures.
- Always use specific search and file viewing tools to inspect actual implementations before writing or editing code.
- Check `src/data/types.ts`, `src/engine/types.ts`, and relevant store contracts before modifying any connected logic.

---

## 3. Planning & Approval Workflow

- For any complex or multi-step task, analyze the codebase first and present a clear implementation plan before making modifications.
- Detail the exact files being modified, the proposed changes, and the verification steps.
- Verify every change immediately using:
  - `bun run typecheck` (`tsc --noEmit`)
  - `bun run test` (Vitest test suite)
  - `bun run lint` (ESLint)

---

## 4. Strict Design System & Token Discipline (Light Theme Only)

- **Strictly Light Theme Only**: Algora has a single unified light theme defined in `src/styles.css`.
  - Background: `--paper` (`#f7f9f8`)
  - Cards / Surface: `--card` (white `#ffffff`)
  - Borders: `--hairline` (`#e4e9e7`)
  - Headings / Body: `--ink` (`#0e1513`)
  - Muted Text: `--slate` (`#5b6763`), Caption: `--slate-soft` (`#8a9591`)
  - Single Accent: Teal (`--highlight` `#14b8a6`, `--accent-strong` `#0b7f6d`, `--tint` `#e6f5f2`)
- **Strictly Forbidden**:
  - NO dark mode / dark panels / black boxes.
  - NO purple, violet, or rainbow gradients.
  - NO glowing blobs, neon highlights, or glassmorphism.
  - NO raw/hardcoded hex colors in components (e.g. `#123456`, `bg-white`, `text-black`). Use token classes only (`bg-paper`, `text-ink`, `border-hairline`, `bg-viz-active`, etc.).
  - NO emoji icons (use `lucide-react` with 1.5px stroke).
  - NO stock photos of people or lorem ipsum placeholder text.

---

## 5. Architecture & Import Boundaries

Maintain strict architectural decoupling across layers:

1. **Visualization Renderers (`src/components/viz/`)**:
   - Must remain **pure presentation components**: `(props: { frame; className? }) => JSX`.
   - **FORBIDDEN** to import Zustand stores (`stores/*`), `engine/registry.ts`, or `@tanstack/react-router`.
2. **Pure Domain Logic (`src/lib/`)**:
   - Must remain pure functions taking data parameters (e.g., `ProgressData`) and returning plain objects.
   - **FORBIDDEN** to import React, DOM APIs, or Zustand stores directly.
   - Every `lib/*` utility must be accompanied by unit tests in `src/lib/__tests__/` or `src/lib/*.test.ts`.
3. **Engine Runtime (`src/engine/`)**:
   - `StepBuilder` must be used for all algorithm modules.
   - Frames and auxiliary panels must be deep-cloned per step to prevent memory aliasing.
4. **State Layer (`src/stores/`)**:
   - Persistent user state lives exclusively in `progressStore` (`algora-progress` key).
   - Dynamic player state uses `createPlayerStore()` factory (via React Context).

---

## 6. SSR & Hydration Safety

- Never read `localStorage`, `Math.random()`, or `Date.now()` during initial server render or client hydration.
- For reading persisted store data, always use the `useHydrated()` hook.
- For pseudo-random cohort generation (e.g., weekly leagues), use deterministic seeded PRNG (`mulberry32` in `src/lib/league.ts`).

---

## 7. Forbidden Files & Config Rules

- **DO NOT hand-edit `src/routeTree.gen.ts`** — this file is automatically generated by TanStack Router.
- **DO NOT create a `tailwind.config.ts` or `tailwind.config.js`** — Tailwind v4 configuration is exclusively handled inline in `src/styles.css` via `@theme inline`.
- **DO NOT rewrite git history** (rebase/force-push on connected Lovable branches).

---

## 8. Quality & Verification Gates

Before finishing any task:

1. Ensure all Vitest unit tests pass (`bun run test`).
2. Ensure TypeScript compilation passes with zero errors (`bun run typecheck`).
3. Ensure ESLint passes (`bun run lint`).
